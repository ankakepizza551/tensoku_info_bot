# 天則インフォメーション管理BOT

東方非想天則の対戦コミュニティ「天則コソ練広場」で動いている Discord Bot です。
レーティング対戦、対戦募集、SOKKUMAN、陣取り戦、戦績管理、投稿・アンケート・お便りなど、サーバー運営に必要な機能をまとめています。

**ユーザーの操作は、チャンネルに設置された「パネル」のボタンが中心です。** スラッシュコマンドは、ボタンと同じ操作をコマンドで呼び出す手段、または管理者が設定・運営するための手段として用意されています。

紹介ページ: https://kosoren-site.kentatoonimusya.workers.dev/

## 対戦

### 有頂天の塔（レーティングマッチ）

希望するレート差を決めてキューに入ると、お互いの希望範囲に収まる相手と自動でマッチングします。対戦のたびにレートとランク（[全9段階](#ランク一覧)）が更新され、ランクのロールも自動で付与されます。

**操作パネルのボタン**（`/setup_rating_panel` で設置）

| ボタン | 動作 |
|---|---|
| 📝 プロフィール登録/変更 | 1戦目のキャラ、IP/接続情報、オートパンチ有無、giuroll有無、コメントを登録 |
| ⚔️ キューに参加 | 希望する最大レート差をドロップダウンで選んでキューに参加 |
| 🚪 キューから抜ける | キューから離脱 |
| 📋 待機状況を見る | 現在の待機者を表示 |
| 🎚 希望レート差を設定 | 希望する最大レート差を変更 |
| 🏆 レーティングスタッツ | 自分のレート・ランク・戦績を表示 |

**マッチ成立後の流れ**

1. 対戦用のスレッドが作られ、双方のプロフィールと接続情報が表示されます。
2. 対戦後、どちらかが **📝 結果を報告する** を押し、勝利本数を入力します。
3. 報告後は **🔁 結果を修正する** で修正できます。
4. スレッド内には **📊 自分のスタッツ** と **🗑️ スレッドを削除** のボタンもあります。

**コマンド**

| コマンド | 内容 |
|---|---|
| `/rating_register` | プロフィールの登録・変更 |
| `/rating_stats` | スタッツ表示 |
| `/rating_queue_join` | キューに参加 |
| `/rating_queue_leave` | キューから離脱 |
| `/rating_queue_status` | キューの状況表示 |

管理者用: `/setup_rating_room`（対戦スレッドの投稿先設定）、`/setup_rating_panel`（操作パネル設置）、`/setup_rating_queue_board`（待機人数を常時表示するボードを設置）、`/setup_rank_roles`（ランクロールの作成と既存メンバーへの付与）

### 対戦募集（フォーラム）

フォーラムチャンネルに募集スレッドを立てる方式です。申し込みから結果報告までスレッド内のボタンで進みます。

**募集パネルのボタン**（`/setup_recruit_panel` で設置）

| ボタン | 動作 |
|---|---|
| ⚔️ 対戦を募集する | 募集フォームを開く（タイトル、IP or クラ専、対戦設定、使用キャラ、回数/コメント） |
| 📝 プロフィール登録/変更 | フォームの初期値を登録 |
| 📊 自分のスタッツ | 自分の戦績を表示 |

**募集スレッド内のボタン**

| 状況 | ボタン |
|---|---|
| 受付中 | ⚔️ 対戦を申し込む / 📊 自分のスタッツ / 🚫 募集を終了する / 🗑️ スレッドを削除 |
| 対戦中 | 📝 結果を報告する / 📊 自分のスタッツ / 🗑️ スレッドを削除 |

結果を報告すると、戦績の登録とEloレーティングの計算が自動で行われます。

**コマンド**: `/recruit_register`（フォームの初期値を事前登録）／管理者用 `/setup_recruit_panel` `/remove_recruit_panel`

### 対戦募集（メッセージ式）

チャンネルに募集メッセージを投稿する方式です。

- **コマンド**: `/recruit [comment: 募集コメント] [format: 募集形式]`
- 募集メッセージのボタン: 「対戦を申し込む」「募集キャンセル」「募集を締め切る」「再募集する」
- 対戦成立後は「結果を報告する」から、スコアと使用キャラを入力するモーダルで戦績が登録されます。

### 戦績の登録・スタッツ・ランキング

| コマンド | 内容 |
|---|---|
| `/report` | 対戦結果を登録。双方のEloレーティングが自動更新されます |
| `/delete_match` | 戦績をIDで削除。報告者本人または管理者のみ。レート変動も巻き戻されます |
| `/stats [user]` | レーティング、総合戦績、使用キャラTOP3、よく戦う相手TOP3、直近の対戦を表示 |
| `/leaderboard [min_matches]` | レーティング順のサーバーランキング |

## 企画

### SOKKUMAN

初級者が「対応可能」な上級者に挑む1vs1の企画です。

**パネルのボタン**（`/setup_sokkuman_panel` で設置）

| ボタン | 動作 |
|---|---|
| 🔰 初級者として登録 | 初級者として登録 |
| ⚔️ 上級者として登録 | 上級者として登録 |
| 🔄 対応状況を切り替える（上級者用） | いま対戦を受けられるかどうかを切り替え |

上級者の対応状況は、`/setup_sokkuman_status_board` で設置するボードに常時表示されます。

**管理者用**: `/setup_sokkuman`（カテゴリ・ロール・チャンネルの一括作成）、`/setup_sokkuman_panel`、`/setup_sokkuman_status_board`、`/sokkuman_registered_list`（登録者一覧をコピペ用テキストで出力）、`/sokkuman_cleanup`（終了後の片付けとデータリセット）

### 陣取り戦

参加者がチームに分かれ、1対1の勝敗でチームの陣地を広げていく期間限定の団体戦です。

最終的に**陣地マップのマス数が最も多いチームが優勝**です。開始時は各チームのマス数が同じで、中央の1マス（⬜）だけがどのチームにも属さない中立マスです。

**少人数での開催について**

- 最低人数はチーム数と同じです。2チーム戦は2人から、4チーム戦は4人から開催できます（`/territory_draw` は、登録済みの参加者がチーム数より少ないと実行できません）。
- 2人で開催すると、1人ずつ2チームに分かれ、2人とも大将になります。
- 大将は各チームに1人。上級者が足りない場合は、次に強い人から選ばれます（`/territory_draw` で直接指定することもできます）。
- 大将の強さは上級者なら5ですが、中級者・初級者が大将になった場合は本人の強さ（2・1）のまま扱います。
- 2チーム戦で参加者が8人以下のときは、陣地マップが 5×5 に縮小され（通常は 7×7）、上級者の大将の強さが 4 に（通常は 5）、大将撃破ボーナスが +1 に（通常は +2）、下剋上ボーナスが最大 +2 に減ります。
- チームの人数に差があるときは、人数の少ないチームのメンバーが1周に複数回出場できます（同じ相手とは1周に1回まで）。

**登録パネル**（`/setup_territory_register_panel`）と**情報パネル**（`/setup_territory_info_panel`）

| ボタン | 動作 |
|---|---|
| 📝 陣取りゲーム プロフィール登録/変更 | 強さ（1:初級 / 2:中級 / 3:上級）、IP/接続情報、オートパンチ、giuroll、コメントを登録 |
| 👤 自分のプロフィール確認 | 自分の登録内容を表示 |
| 📋 登録者一覧 | 登録済みプロフィールを一覧表示 |
| 🗂️ チーム分け結果 | 現在のチーム分けを表示 |
| 📖 ルール説明 | ルールを自分だけに表示（チーム分け後は、その大会の人数・盤面・周回数に合わせた内容） |

**対戦パネル**（`/setup_territory_battle_panel`）

| ボタン | 動作 |
|---|---|
| ⚔️ 対戦結果を報告 | 対戦相手を選び、結果を入力 |
| 📊 現在の戦況 | 陣地のマス数・侵略度・出場状況を表示 |
| 🗑️ 対戦結果を削除 | Match IDを指定して削除 |
| 🗺️ 陣地マップ | 現在の陣地マップを表示 |

**コマンド（誰でも使える）**

| コマンド | 対応するボタン | 役割 |
|---|---|---|
| `/territory_register` | 📝 陣取りゲーム プロフィール登録/変更 | プロフィールを登録・更新。登録すると「陣取り参加者」ロールが付く |
| `/territory_profile` | 👤 自分のプロフィール確認 | 自分のプロフィールを表示 |
| `/territory_list` | 📋 登録者一覧 | 登録済みの全員を一覧表示 |
| `/territory_teams` | 🗂️ チーム分け結果 | 現在のチーム分けを表示 |
| `/territory_rules` | 📖 ルール説明 | ルールを自分だけに表示 |
| `/territory_report` | ⚔️ 対戦結果を報告 | 1対1の結果を登録。勝ったチームが塗るマスを選ぶ |
| `/territory_score` | 📊 現在の戦況 | 陣地のマス数・侵略度・出場状況を表示 |
| `/territory_map` | 🗺️ 陣地マップ | 現在の陣地マップを表示 |
| `/territory_match_delete` | 🗑️ 対戦結果を削除 | 対戦IDを指定して削除（塗ったマスも元に戻る）。削除できるのは**報告者本人か、Discordの管理者（Administrator）権限を持つ人だけ**。「サーバー管理」権限だけでは、他人の報告は削除できない |

**管理者用コマンド（サーバー管理権限が必要）**

| コマンド | 役割 |
|---|---|
| `/territory_setup` | 初期セットアップを一括で行う（カテゴリ・参加者ロール・チャンネルの作成と、全パネルの設置） |
| `/setup_territory_register_panel` | 登録パネルを設置 |
| `/setup_territory_info_panel` | 情報パネルを設置 |
| `/setup_territory_battle_panel` | 対戦パネルを設置 |
| `/territory_draw` | チーム分け抽選。2チームか4チームを選び、大将（最大4人）や周回数 `rounds`（1〜10）も指定できる。「陣取り参加者」ロールを持つ登録者が対象。`rounds` を指定すると、全員の対戦が終わるたびに自動で次の周へ進み、最終周の後に最終結果を自動で発表 |
| `/territory_new_round` | 周回を進め、全員を再出場可能にする（周回数を指定していない大会で使う） |
| `/territory_end` | 大会終了と最終結果の発表。陣地のマス数が最も多いチームが優勝、同数なら中央マスを持つチーム、それでも決まらなければ侵略度合計で判定 |
| `/territory_cleanup` | 終了後の片付け（チームロール・チャンネルの削除とデータリセット） |

**Botが作るロールとチャンネル**

- **陣取り参加者**（ロール）: プロフィールを登録すると付きます。チーム分けの対象は、このロールを持つ登録者です。
- **Aチーム〜Dチーム**（ロール）: チーム分けのときに作成・付け替えされます（メンション可）。
- **チャンネル**: `陣取り-受付` `陣取り-本部` `陣取り-参加者雑談` `陣取り-参加者VC`、チームごとの `陣取り-Aチーム` `陣取り-Aチーム-VC` など。基本は「陣取りゲーム」カテゴリの中に作られます。

#### 配信オーバーレイ（OBS）

陣取りマップを配信画面に映すための、OBSブラウザソース用ページです。Bot本体に組み込まれた軽量Webサーバー（`overlay/server.py`）が提供します。

- **URL**: `https://<Railwayで割り当てた公開ドメイン>/territory?guild_id=<サーバーID>`
- 背景は透過で、一定間隔で自動更新されます。
- **公開設定（初回のみ）**: Railwayダッシュボードでこのサービスの「Settings」→「Networking」から Public Domain を発行してください。
- **アクセス制限（任意）**: `.env` に `TERRITORY_OVERLAY_TOKEN=好きな文字列` を設定すると、URLに `&token=同じ文字列` を付けないと表示されなくなります。

### 天則 HOT TIME

毎週木曜 **21:00〜24:00** は「コソ練広場 天則 HOT TIME」です。みんなが同じ時間に集まって対戦できるよう、Botが自動でお知らせします。

| 時刻 | 投稿内容 |
|---|---|
| 木曜 9:00 | 今夜HOT TIMEがあることの予告。「🙋 今夜行けます」ボタンと、通知ロールの登録ボタン付き |
| 木曜 21:00 | 開始のお知らせ。有頂天の塔の待機人数、対戦募集（フォーラム）の募集中の件数、「今夜行けます」の人数を表示 |
| 金曜 0:00 | 結果のまとめ。対戦数・参加人数、対戦数トップ3、レート上昇トップ3 |

- 予告の「🙋 今夜行けます」を押すと、予告に人数と名前が表示されます。押した人は、21:00の開始のお知らせで個別にメンションされます（通知ロールの有無は関係ありません。50人を超えた分はメンションしません）。「取り消す」で取り消せます。受付はその日の24:00までです。
- 予告と開始のお知らせでは、通知ロールをメンションします。ロールはパネルの「🔔 通知を受け取る」「🔕 通知をやめる」で、各自が付け外しできます。
- まとめの対象は、21:00〜24:00に報告された確定済みの戦績です。24:00を過ぎてから報告した戦績は含まれません。
- `/hot_time_result` で、前回の結果（開催中なら途中経過）をいつでも確認できます。
- HOT TIMEの間は、有頂天の塔の操作パネルと待機状況ボードの見出しが「🔥 HOT TIME開催中！」に変わり、色も赤になります。待機列に最初の1人が入ったときの告知にも「🔥 HOT TIME開催中！」が付きます。21:00と24:00に自動で切り替わります。
  - 操作パネルの切り替えは、この機能を入れた後に `/setup_rating_panel` で設置したパネルだけが対象です。それより前に設置したパネルは、一度設置し直してください（古いパネルは削除して構いません）。
- 月間MVPに「🔥 HOT TIME対戦数MVP」部門があり、その月のHOT TIME中（木曜21:00〜24:00）に報告された対戦数の上位3名を表彰します。ほかの部門と同じく、同じ相手との対戦は1日5戦までしか数えません。該当者がいない月は、この部門は表示されません。公開API（`/api/public/mvp`）では `hot_time` として返します。
- `/hot_time_setup` を行うと、イベントカレンダーと公開サイトのカレンダーにも、毎週木曜のHOT TIMEが 🔥 で表示されます。これは毎週の予定として自動で表示するもので、カレンダーの編集・削除の対象にはなりません。`/hot_time_stop` で表示も消えます。
- Botが止まっていて予定の時刻に投稿できなかった場合、予告は21:00まで、開始のお知らせは24:00まで、まとめは金曜12:00までに起動すればその時点で投稿します。

管理者用: `/hot_time_setup`（投稿先チャンネルと通知ロールを設定）、`/hot_time_panel`（通知ロールのパネルを設置）、`/hot_time_stop`（自動投稿を止める）。設定した時点で予定時刻を過ぎているお知らせは、その週は投稿されません。通知ロールは、Botのロールより下に置いてください。メンションできない設定のロールを使う場合は、Botに「@everyone、@here、全てのロールにメンション」の権限が必要です。

## 交流・投稿

### メインキャラ登録と分布

メインキャラを1人だけ登録できます（いつでも変更可）。サーバー内の使用率をゲージつきで見られ、キャラを選ぶとそのキャラの使用者一覧が自分にだけ表示されます。

- **パネルのボタン**（`/main_char_panel` で設置。管理者用）: 「メインキャラを登録・変更」「分布を見る」
- **コマンド**: `/main_char`、`/main_char_list`

### 記事投稿（フォーラム）

見出し・引用・画像を使った記事風の投稿を、フォーラムチャンネルへ作成します。

**パネルのボタン**（`/setup_article_panel` で設置）: 📝 記事を投稿する（投稿先のフォーラムを選択）

**エディタのボタン**

| 行 | ボタン |
|---|---|
| 1 | 📝 タイトル・本文 / 🖼️ 画像 / 🎨 カラー |
| 2 | 𝐁 太字 / 𝐼 斜体 / `C` コード / ❝ 引用 / ＃ 見出し |
| 3 | 📤 フォーラムに投稿 / ❌ キャンセル |

投稿後のスレッドには **✏️ 記事を編集** と **🗑️ スレッドを削除** のボタンが付きます。

管理者用: `/setup_article_panel` `/remove_article_panel`

### 簡易投稿・Embedビルダー

| コマンド | 内容 |
|---|---|

#### 公開サイト向けAPI

紹介サイトに「サーバーの今」を表示するための、読み取り専用の集計APIです（`overlay/public_api.py`）。同じWebサーバー上で動きます。

- **URL**: `GET https://<公開ドメイン>/api/public/stats`
- **返す内容**: 有頂天の塔のランク別人数、メインキャラごとの登録人数。ユーザー名・ID・個別のレートは含みません。
- **キャッシュ**: 60秒
- **カレンダー用**: `GET /api/public/events` は、カレンダーの予定一覧（日付・大会名・種別・時間・場所・URL）を返します。HOT TIMEを設定している場合は、毎週木曜のHOT TIMEも `"recurring": true`（IDは負の数）として、前月から6か月先までの分を含めます。Webのカレンダーはこの予定を読んで表示します。`PUBLIC_GUILD_ID` を設定すると、そのサーバーの予定だけに絞れます。
- **CORS**: 既定は全許可。制限する場合は `PUBLIC_API_ORIGINS=https://kosoren-site.xxx.workers.dev`（カンマ区切り）を設定します。

## セットアップ

### 1. 前提

- Python 3.10 以上
- Discord Bot アカウント（**Message Content Intent** と **Server Members Intent** を有効にしてください）

### 2. インストール

```bash
pip install -r requirements.txt
```

### 3. 環境変数

`.env` をプロジェクトルートに作成します。

```env
DISCORD_TOKEN=Botのトークン
BOT_PREFIX=!
DB_PATH=data/tensoku_stats.db
LETTER_ADMIN_CHANNEL_ID=お便りの送信先チャンネルID（数字）
SERVER_INVITE_URL=https://discord.gg/xxxxxxxx
TERRITORY_OVERLAY_TOKEN=（任意）配信オーバーレイ用のアクセス制限トークン
```

| 変数 | 内容 |
|---|---|
| `DISCORD_TOKEN` | Botのトークン |
| `BOT_PREFIX` | オーナー用プレフィックスコマンドの接頭辞（未設定時は `/`） |
| `DB_PATH` | SQLiteのパス。未設定時は `data/tensoku_stats.db` |
| `LETTER_ADMIN_CHANNEL_ID` | お便りと確認ログの送信先 |
| `SERVER_INVITE_URL` | `/promote` で使う招待リンク |
| `CALENDAR_EDITOR_ROLE_ID` | （任意）カレンダーの予定を編集できる追加ロールのID。未設定ならサーバー管理権限を持つ人だけ |
| `CALENDAR_WEB_URL` | カレンダーの下に出す「Web版を開く」ボタンのURL。未設定ならWeb版カレンダーのURL、空にするとボタンなし |
| `TERRITORY_OVERLAY_TOKEN` | 配信オーバーレイのアクセス制限（任意） |
| `PORT` | オーバーレイのWebサーバーのポート（未設定時は `8080`） |

### 4. 起動

```bash
python main.py
```

起動するとSQLiteのデータベースが自動作成・初期化されます。起動後、オーナーアカウントから `!sync guild` を送信してスラッシュコマンドを同期してください。

### Railway で運用する場合

- `Procfile` は `worker: python main.py` です。
- `RAILWAY_ENVIRONMENT` が設定されている環境では、データベースを `/app/data` のVolumeに置きます。**Volumeが未マウントだと、データが消えるのを防ぐため起動を止めます。** Railwayの Volumes タブで、マウントパス `/app/data` のVolumeを追加してください。
